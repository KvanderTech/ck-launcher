# ЦК Лаунчер: ядро первого Windows-релиза

Дата: 23 августа 2026 года  
Статус: утверждённый дизайн, ожидает финального просмотра

## Цель

Создать первый рабочий релиз «ЦК Лаунчера» для Windows 10 и 11. Релиз должен авторизовать лицензионный Microsoft-аккаунт, показывать официальные версии Minecraft: Java Edition, устанавливать подходящую Java, загружать необходимые игровые файлы и запускать Vanilla Minecraft.

Сборки, Fabric, Forge, NeoForge, Quilt, каталог Modrinth, управление модами, скинами и плащами не входят в первый этап. Архитектура должна позволить добавить их без переработки базового установщика и механизма запуска.

## Технологии

- Tauri — оболочка Windows-приложения и граница между интерфейсом и системными функциями.
- React и TypeScript — интерфейс на основе утверждённого дизайн-макета.
- Rust — авторизация, файловые операции, загрузки, проверка файлов, управление Java и запуск игры.
- SQLite — аккаунты без секретов, профили, настройки и состояние установок.
- Windows Credential Manager — refresh-токены и другие секретные данные.
- WebView2 — отображение интерфейса внутри приложения.

Первый релиз собирается только для Windows x64. Возможность переноса на другие ОС сохраняется на уровне модулей, но не является требованием этапа.

## Архитектурные границы

React отвечает за представление данных и пользовательские действия. Интерфейс не получает refresh-токены, не формирует команды Java и не выполняет произвольные файловые операции.

Rust-ядро предоставляет ограниченный набор Tauri-команд и событий:

- команды начинают авторизацию, установку, проверку и запуск;
- запросы возвращают снимки аккаунтов, версий, профилей и настроек;
- длительные операции публикуют типизированные события прогресса;
- все пути проверяются и нормализуются внутри Rust-ядра.

## Модули ядра

### `auth`

Выполняет OAuth 2.0 Authorization Code Flow с PKCE через системный браузер. После Microsoft OAuth модуль проходит Xbox Live, XSTS и Minecraft Services, получает Minecraft-профиль и проверяет владение Java Edition.

Listener принимает callback только на временном IPv4 loopback-адресе `127.0.0.1` со случайным свободным портом. OAuth redirect в authorize/token запросах имеет точную форму `http://localhost:<port>/callback`; в Entra Mobile and desktop applications регистрируется `http://localhost/callback`, где порт игнорируется, а путь совпадает. Используются `state` и PKCE verifier. Пароли Microsoft приложение не видит.

### `accounts`

Хранит публичные сведения об аккаунтах в SQLite, переключает активный аккаунт и обновляет access-токены. Refresh-токен хранится только в Windows Credential Manager. Удаление аккаунта очищает обе записи.

### `metadata`

Загружает официальный Minecraft version manifest, кэширует его и преобразует данные в собственные типы. В интерфейсе первого этапа показываются стабильные Vanilla-релизы. Архитектура допускает включение snapshots позднее.

### `runtime`

Определяет требуемую Java по метаданным выбранной версии. Поддерживаются Java 8, 17, 21 и 25. Сначала проверяется управляемый runtime лаунчера, затем указанный пользователем путь, затем системные установки.

Если подходящей Java нет, лаунчер предлагает установить управляемый runtime в `%AppData%\CKLauncher\runtime`. Загруженный архив и исполняемый файл проверяются до использования.

### `downloads`

Предоставляет очередь параллельных загрузок с ограничением количества одновременных запросов, временными `.part`-файлами, атомарным завершением, повторными попытками и публикацией прогресса. Уже корректные файлы повторно не загружаются.

### `installer`

Устанавливает version JSON, клиентский JAR, библиотеки, assets и native-библиотеки. Проверяет размер и SHA-хэш, когда они доступны в официальных метаданных. Распаковка natives выполняется в отдельный каталог конкретной версии.

### `profiles`

Хранит имя профиля, выбранную Minecraft-версию, объём памяти, игровой каталог и связанные параметры. На первом этапе создаётся один основной профиль, но модель данных поддерживает несколько профилей.

### `launcher`

Разрешает наследование version JSON, формирует classpath, JVM-аргументы и игровые аргументы, применяет правила ОС и архитектуры, подставляет данные аккаунта и запускает Java как дочерний процесс без shell-интерпретации.

### `storage`

Управляет миграциями SQLite, настройками и путями приложения. Основной каталог данных — `%AppData%\CKLauncher`. Журналы не содержат access-токены, refresh-токены или параметры авторизации.

## Данные интерфейса

Интерфейс получает сериализуемые DTO, независимые от внутренних типов библиотек:

- `AccountSummary`: идентификатор, имя Minecraft, UUID, URL головы и признак активного аккаунта;
- `GameVersionSummary`: идентификатор версии, тип и дата выпуска;
- `LauncherProfile`: версия, память, игровой каталог и состояние установки;
- `JavaRuntimeStatus`: требуемая версия, путь, источник и результат проверки;
- `LaunchProgress`: стадия, текущий файл, завершённые и общие байты, скорость;
- `LauncherError`: стабильный код, понятное сообщение и необязательные технические сведения.

События длительных операций имеют идентификатор операции. Это исключает смешивание прогресса старой и новой установки.

## Пользовательские сценарии

### Первый запуск и вход

1. Приложение создаёт каталог данных и применяет миграции SQLite.
2. Проверяет доступность WebView2 и показывает понятную инструкцию при его отсутствии.
3. Пользователь начинает вход через Microsoft.
4. Системный браузер открывает страницу Microsoft.
5. Loopback callback возвращает код приложению; проверяются `state` и PKCE.
6. Лаунчер получает Xbox, XSTS и Minecraft-токены и проверяет лицензию.
7. Публичные данные сохраняются в SQLite, секрет — в Credential Manager.

### Установка и запуск

1. Пользователь выбирает стабильную версию Minecraft и объём памяти.
2. Лаунчер загружает и кэширует метаданные версии.
3. Определяет требуемую Java и при необходимости устанавливает runtime.
4. Проверяет локальные файлы и формирует план загрузки.
5. Скачивает недостающие файлы с общим и текущим прогрессом.
6. Проверяет результат и формирует команду запуска.
7. Запускает игру, сворачивает окно по настройке и отслеживает процесс.
8. После завершения игры возвращает интерфейс в готовое состояние.

## Настройки первого этапа

- объём памяти от 512 МБ до доступного безопасного максимума с шагом 512 МБ;
- пути Java 8, 17, 21 и 25 с действиями установки, обнаружения и ручного выбора;
- частота смены фоновых кадров;
- поведение окна после успешного запуска игры;
- каталог данных игры с безопасным значением по умолчанию.

Выбора темы нет: первый релиз использует утверждённое тёмное оформление.

## Ошибки и восстановление

- Сетевые операции имеют таймауты, ограниченные повторные попытки и отмену.
- Незавершённые `.part`-файлы не считаются установленными.
- Повреждённый файл удаляется и загружается повторно.
- Истёкший access-токен обновляется автоматически; ошибка refresh требует повторного входа.
- Отсутствие Minecraft: Java Edition показывается отдельным состоянием, а не общей ошибкой.
- Несовместимая Java не используется; предлагается рекомендуемый runtime.
- Ошибка запуска содержит короткое объяснение, код и кнопку открытия очищенного журнала.
- Повторное нажатие «Играть» во время установки или активной игры блокируется.
- Отмена установки оставляет уже проверенные файлы для следующей попытки.

## Безопасность

- OAuth использует системный браузер, loopback callback, PKCE и одноразовый `state`.
- Секреты не передаются React-интерфейсу и не записываются в SQLite или журналы.
- Команда Java создаётся через API процесса с массивом аргументов, без `cmd.exe`.
- Загружаемые файлы записываются только в разрешённые каталоги лаунчера или явно выбранный игровой каталог.
- Пути из метаданных проверяются против выхода за корневой каталог.
- Архивы runtime и natives защищены от path traversal при распаковке.

## Тестирование

### Модульные тесты

- разбор и наследование version JSON;
- правила библиотек для Windows x64;
- выбор Java для разных поколений Minecraft;
- формирование JVM- и игровых аргументов;
- расчёт безопасного максимума памяти;
- очистка секретов из ошибок и журналов;
- проверка путей и архивных записей.

### Интеграционные тесты

- установка фиктивной версии во временный каталог через локальный HTTP-сервер;
- повторный запуск установки без повторной загрузки корректных файлов;
- восстановление после оборванного `.part`-файла;
- повторная загрузка при неверном SHA;
- миграции чистой и существующей SQLite-базы;
- формирование процесса запуска без фактического запуска Minecraft.

### Ручная приёмка

- чистая Windows 10 x64 и Windows 11 x64;
- вход лицензионного Microsoft-аккаунта;
- отказ во входе и аккаунт без Java Edition;
- установка и запуск одной старой версии на Java 8 и современной версии на Java 21;
- потеря сети и продолжение установки;
- переключение аккаунта и повторный запуск;
- отсутствие секретов в логах.

## Критерии готовности

Первый этап завершён, когда подписанная или тестовая Windows-сборка:

1. устанавливается и открывает интерфейс утверждённого дизайна;
2. выполняет Microsoft-авторизацию и безопасно сохраняет аккаунт;
3. показывает стабильные официальные версии Minecraft;
4. определяет или устанавливает подходящую Java;
5. устанавливает файлы выбранной Vanilla-версии с прогрессом и проверкой;
6. запускает лицензионный Minecraft и корректно отслеживает процесс;
7. восстанавливается после типовых сетевых и файловых ошибок;
8. проходит автоматические тесты и ручную приёмку на Windows 10/11.
