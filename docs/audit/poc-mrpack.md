# Статический разбор poc.mrpack

Дата: 7 сентября 2026. Проверены присланный архив и содержимое, полученное в этот день по единственной ссылке из его индекса. Инструкции из переписки на скриншоте не выполнялись: архив не импортировался в рабочий лаунчер, Minecraft и мод из образца не запускались.

## Результат

Это PoC доставки и исполнения Java-мода через установку сборки. Полученный JAR содержит демонстрационный мод, который при инициализации Fabric-клиента пытается:

1. Запустить `rundll32.exe` с обработчиком URL и открыть GitHub-профиль `YourMayskiy` в системном браузере.
2. Записать `AUDIT_POC_EXECUTED.txt` в каталог `user.home`, обычно домашнюю папку пользователя Windows.

Это установлено дизассемблированием всего единственного класса, а не только поиском строк. В этом классе не обнаружены кража токенов, шифрование файлов, закрепление в системе или загрузка дополнительных программ. Это вывод о конкретных исследованных байтах, а не гарантия для будущего содержимого ссылки.

## Как образец проходит через лаунчер

На исследованном [main, content.rs](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/commands/content.rs#L752):

1. `FileHashes` разрешает отсутствующие SHA-512 и SHA-1. Пустой объект успешно разбирается.
2. Формат/игра проходят проверку, выбранный Fabric-профиль устанавливается до проверки всех файлов.
3. URL из `downloads[0]` передаётся в HTTP-клиент.
4. В `download_bytes` обе условные проверки хеша пропускаются, и байты считаются принятыми.
5. Байты записываются в каталог модов.
6. Если затем Minecraft с Fabric успешно запускается, Fabric вызывает entrypoint мода.

Сам импорт не равнозначен запуску этого класса. В `main` дополнительно есть ошибка classpath, рассмотренная в PR №1; end-to-end выполнение PoC в текущем лаунчере не проверялось. Статически подтверждены принятие незакреплённого файла и назначение его как мода.

В присланном индексе нет обхода каталогов через `../`, внедрения shell-команды в имя пути или эксплуатации Qt/Tauri/WebView2. Запуск стороннего кода — нормальная возможность Java-модов; проблема лаунчера заключается в неограниченной установке недоверенного содержимого и отсутствии проверки целостности/доверия. PoC не демонстрирует повышение привилегий.

## Что исправить

- Отклонять пустые/неверные хеши и неподдерживаемые источники до загрузки или изменения сборки.
- Проверять фактический размер, контрольные суммы и перенаправления; скачивать в ограниченный staging-каталог.
- До установки локального файла показывать название, версию игры, загрузчик и источники; явно пояснять, что моды выполняют программы с правами игры.
- Не запускать игру автоматически вследствие открытия вложения; текущий код автоматически импортирует ассоциированный `.mrpack`, но отдельного автоматического запуска игры в этом пути не обнаружено.
- Сохранять происхождение и хеши установленного состава для последующей проверки/восстановления.
- Для повышенной изоляции рассматривать отдельную ограниченную учётную запись/среду, понимая, что обычный Fabric не обеспечивает песочницу для модов. Хеширование не является антивирусом.

Нужные регрессионные проверки: пустые хеши, неверный SHA-512/SHA-1, сменившееся содержимое по той же ссылке, превышение размера, недопустимое перенаправление, отказ без частичной установки, корректный обычный модпак. Для этого достаточно локального тестового HTTP-сервера и безвредных байтов; запускать полученный PoC в тестах не требуется.
