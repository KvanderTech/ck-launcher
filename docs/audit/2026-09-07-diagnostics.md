## Приоритетные находки

P1 — исправить до расширения распространения; P2 — устранить в ближайшем цикле. «Подтверждено кодом» означает прослеженный путь выполнения, а не запуск атаки.

### 1. P1 — файлы модпаков принимаются без контрольных сумм и политики адресов

[content.rs:1033](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/commands/content.rs#L1033): `download_bytes` проверяет SHA-512 или SHA-1 только при наличии соответствующего поля. Если `hashes: {}`, результат скачивания возвращается как успешный. URL из архива поступает непосредственно в HTTP-клиент; отдельной проверки HTTPS, допустимых источников и перенаправлений нет.

Присланный образец использует именно отсутствие хеша. Подмена содержимого по той же ссылке не будет обнаружена. Для других специально подготовленных архивов код также допускает HTTP-запросы к произвольным адресам; обращения к локальным службам в этом аудите не выполнялись.

**Исправление:** обязательный корректный хеш до первого запроса; сверка размера и хеша до установки; политика HTTPS и источников с проверкой каждого перенаправления. Для внешних источников нужна осознанная модель доверия. Одного добавления SHA-512 недостаточно: автор вредоносного мода может указать правильный хеш. Любой Fabric-мод является исполняемой программой с правами запущенной игры.

### 2. P1 — импорт не ограничивает распакованный размер и потребление памяти

[content.rs:752](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/commands/content.rs#L752): индекс читается целиком; ограничения количества ZIP-записей и общего распакованного размера отсутствуют; `overrides` копируются без лимита. Сетевая загрузка использует `bytes().to_vec()`. Ограничение локального `.mrpack` в 1,5 млрд байт проверяется **после** `fs::read`.

Это создаёт путь к переполнению памяти/диска и зависанию на большом либо специально сжатом архиве. В отличие от этого, модуль распаковки Java уже содержит лимиты числа записей и общего размера.

**Исправление:** проверять размер файла до чтения, ограничивать фактически прочитанные байты, индекс, число записей, размер одного файла и общий объём; скачивать потоком в staging-каталог; поддержать отмену. Не полагаться исключительно на размеры, объявленные недоверенным ZIP/HTTP-сервером.

### 3. P1 — проверки путей в библиотеке слабее, чем в основном установщике

[content.rs:1116](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/commands/content.rs#L1116): `safe_relative` отклоняет очевидные абсолютные пути и `..`, но затем просто соединяет путь с корнем. Здесь нет проверки существующих junction/symlink/reparse point, Windows ADS, имён устройств и коллизий служебных файлов.

**Условие выхода из каталога через junction:** такой объект уже должен существовать в дереве сборки. Представленный PoC его не создаёт. Нельзя называть это подтверждённым Zip Slip именно в присланном файле.

**Исправление:** единые правила путей для Vanilla, модов, `overrides`, просмотра и удаления; проверка компонентов непосредственно перед записью и создание файлов без перехода по ссылкам. Уже имеющиеся `AppPaths::safe_join` и строгий валидатор Windows следует использовать как основу, учитывая гонку между проверкой и записью.

### 4. P1 — просмотр файла может передать его на выполнение Windows

[content.rs:1757](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/commands/content.rs#L1757) передаёт выбранный файл аргументом `explorer.exe`. [LibraryPage.tsx](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src/features/library/LibraryPage.tsx) вызывает эту команду по кнопке «Показать» и двойному нажатию. Для исполняемых файлов и некоторых ассоциаций это потенциально запускает содержимое, хотя пользователь ожидает просмотр.

**Исправление:** папку открывать, файл выделять через `SHOpenFolderAndSelectItems`; текст показывать отдельным просмотрщиком. `.exe`, `.cmd`, `.lnk` из сборки не должны запускаться действием «Показать». Динамическая проверка с исполняемым вложением не проводилась.

### 5. P1 — ошибка запуска Java уже подтверждена и исправляется в PR №1

[profiles/mod.rs](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/profiles/mod.rs#L159) возвращает результат `canonicalize`, а [classpath.rs](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/launcher/classpath.rs#L15) использует этот корень в аргументах JVM.

Контрольный Java-класс в обычном каталоге запустился. Тот же classpath с Windows-префиксом `\\?\` дал `ClassNotFoundException`. Это ошибка передачи пути дочернему процессу, а не графического движка.

**Действие:** проверить и включить существующий PR №1, сохранив проверки канонического пути до преобразования на границе JVM. Отдельно проверить UNC, кириллицу, пробелы, длинные пути и старую Java. Поддержка очень длинных путей не появляется автоматически от удаления префикса.

### 6. P1 — Minecraft 1.17.x упирается в отсутствие Java 16

[runtime/mod.rs:23](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/runtime/mod.rs#L23) допускает только 8, 17, 21 и 25. `requirement_for_version` передаёт major из метаданных в этот ограниченный список. [Официальный JSON Minecraft 1.17.1](https://piston-meta.mojang.com/v1/packages/e0e7ab5ed6f55bbd874ef95be3c9356d67e64b57/1.17.1.json) содержит `majorVersion: 16`.

Следовательно, текущий путь отклоняет эту версию с `unsupported_java_version` ещё до нормального выбора runtime.

**Исправление:** добавить согласованную политику Java 16 во все уровни — backend, типы интерфейса, выбор и установку runtime. Альтернативный запуск на Java 17 разрешать лишь для проверенных сочетаний версии игры и загрузчика, а не простой заменой числа.

### 7. P1 — требование Windows 7/8.1 не выполнено текущей архитектурой

README заявляет только Windows 10/11 x64. Обычные Windows-targets Rust начиная с 1.78 имеют минимальную Windows 10; текущий `Cargo.toml` не задаёт отдельную legacy-сборку. Qt 6 также не является готовым решением для Windows 7/8.1.

**Решение:** [отдельный план перехода на Qt и матрица совместимости](qt-windows-plan.md). До проверки всего набора зависимостей нельзя обещать поддержку Windows 7 заменой одного UI-пакета.

### 8. P2 — запуск интерфейса зависит от доступности каталога Mojang

[App.tsx:244](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src/app/App.tsx#L244): сетевой каталог включён в общий `Promise.all` первичной загрузки. Его отказ переводит весь старт в ошибку.

Это также затронуто в PR №1. Предлагаемый там `catch` предотвращает общий отказ, но интерфейс всё ещё ожидает завершения сетевого запроса. Следующий шаг — показывать локальную библиотеку независимо от каталога и обновлять каталог в фоне. Это относится к открытию лаунчера; возможность лицензионной игры без сети требует отдельной политики авторизации.

### 9. P2 — «Восстановить» не работает для локального `.mrpack`

[content.rs:629](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/commands/content.rs#L629): ремонт любого объекта типа `modpack` запрашивает проект и версию у Modrinth. Локальный импорт сохраняет искусственный `project_id` вида `local-mrpack-...` и `version_id = local`, которых в API нет.

**Исправление:** хранить происхождение, локальный индекс и хеш исходного архива; для локальной сборки восстанавливать по сохранённому плану либо просить исходный файл. Для удалённой сборки использовать конкретный релиз.

### 10. P2 — состояние установленных модов расходится с файлами

[Удаление](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/commands/content.rs#L1405) сначала удаляет запись БД, игнорирует ошибку файловой операции и не учитывает суффикс `.disabled`. Удаление отключённого мода оставляет его файл. [Ремонт](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/commands/content.rs#L629) вызывает `install_regular`, который снова пишет обычный файл и устанавливает `enabled: true`.

**Исправление:** сохранять состояние отключения при ремонте; удалять фактический файл с откатом/согласованием БД; сообщать о неудаче. Для обновления мода также нужен учёт старого имени файла, чтобы разные версии не оставались одновременно в `mods`.

### 11. P2 — импорт может нарушать состав и версии сборки

[content.rs:786](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/commands/content.rs#L786): учитываются Fabric/Quilt, а прочие зависимости загрузчика попадают в ветку Vanilla. Поэтому Forge/NeoForge-модпак может установиться с неверным загрузчиком вместо раннего понятного отказа.

В рекурсивной установке обязательных зависимостей передаётся `None` вместо указанного `dependency.version_id`; зависимости только с `version_id` пропускаются. Повторная установка может получить другую версию зависимости.

**Исправление:** валидировать загрузчик до изменений на диске; хранить и соблюдать конкретные версии; не достраивать состав модпака непредсказуемо. Forge/NeoForge реализовать отдельным этапом либо явно отклонять.

### 12. P2 — просмотр журналов обходит заявленное очищение

[content.rs:1740](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/src/commands/content.rs#L1740): `read_build_log` читает исходный файл Minecraft, а затем возвращает последние 2 МБ в WebView без redaction. Перед усечением весь файл уже загружен в память. Это другой путь, чем очищенный журнал основного `launcher::process`.

**Исправление:** ограниченное чтение хвоста, общий фильтр секретов до передачи в UI и отдельный экспорт очищенного журнала. Конкретный секрет в пользовательских логах не искался; нарушение границы видно из кода.

### 13. P2 — нет общей блокировки изменений сборки

Команды установки контента, ремонта, переключения и удаления сборки не используют общий механизм занятости с запуском игры. Файловые записи используют фиксированные имена `.part`; возможны пересечения операций. Синхронные файловые операции и рекурсивный `directory_size` также выполняются в путях async-команд без ограничения глубины обхода ссылок.

**Исправление:** очередь операций с блокировкой на сборку, запрет опасных изменений во время игры, уникальный staging и отмена, тяжёлый файловый обход вне обработчика интерфейса, проверка ссылок и ограничение работы.

### 14. P2 — проверки и интерфейс не соответствуют текущим сценариям

Все 10 наблюдённых frontend-ошибок начинаются с ожидания прямого запуска после «Играть» на главной. В текущем [App.tsx:544](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src/app/App.tsx#L544) эта кнопка только открывает библиотеку. Эти результаты нельзя выдавать за 10 независимо подтверждённых ошибок backend.

Нужно согласовать поведение кнопки с продуктовым решением и обновить сценарные тесты, сохранив проверки очереди сохранения памяти, отмены и устаревших событий. `jsdom` дополнительно сообщает о неподдерживаемом `Audio.play`; звук следует подменить в тестовой среде.

Тестовый `installer_asset_index.json` содержит 193 байта с CRLF, тогда как ожидаются 192 байта и SHA-1 `f12c6162a8b2dfc72557cbcf499f3dcffd772df0`. После нормализации LF ожидания совпадают. Следует добавить правило LF для хешируемых фикстур в `.gitattributes`, не отключая проверку хеша.

В репозитории не найдены workflows CI; GitHub Actions API вернул 0 запусков. Нужны frontend-сборка/тесты и Rust-проверки при каждом PR, затем smoke-проверки установщика на целевых ОС.

### 15. P2 — фиксированное окно и тяжёлый первый экран

[tauri.conf.json](https://github.com/KvanderTech/ck-launcher/blob/09b2e886b361fa419996658d730f705cd08e528d/app/src-tauri/tauri.conf.json) ограничивает окно ровно 1280×720. При 1366×768 и масштабе Windows 125% доступная логическая область меньше этих размеров. Нужны адаптивный минимум, изменение размера, прокрутка и проверка 100/125/150/200% DPI.

Сборка выдаёт единый JS-файл около 840 КБ до gzip; изображения и несжатые WAV добавляют несколько мегабайт. Предпросмотр скинов стоит загружать при открытии страницы, останавливать скрытый рендеринг, уменьшить изображения и звуки. При переходе на Qt это следует учитывать как требования к новому интерфейсу.

## Зависимости и выпуск

OSV-совпадения в `Cargo.lock` не означают 18 эксплуатируемых уязвимостей Windows-лаунчера. Среди них GTK/GLib для других платформ, сообщения о прекращении сопровождения библиотек и `rsa`, появившийся через SQLx/MySQL в lock-файле. Cargo.toml включает SQLite, поэтому присутствие MySQL/RSA в lock ещё не подтверждает включение в итоговый бинарник. После появления Rust-среды нужен `cargo tree` для Windows и реально включённых features, затем RustSec-аудит с пояснением применимости каждого результата.

Положительное: npm-аудит сейчас чистый, закреплённые SHA-256 Java совпали с опубликованными Temurin, ключ проверок обновлений хранится как публичная конфигурация. Закрытый ключ обновлений не нужен для загрузки исходников в GitHub и не должен пересылаться для обычной работы над PR.

Для выпуска нужны воспроизводимая Windows-сборка, проверка подписи и установки/обновления на чистом профиле, отдельные stable/beta/legacy-каналы, тесты миграции реальных старых баз и резервная копия перед несовместимыми изменениями. Подпись обновления Tauri и подпись издателя Windows — разные проверки.

## Рекомендуемая последовательность

1. Согласовать и включить PR №1; подтвердить запуск Vanilla/Fabric/Quilt на обычных и кириллических путях.
2. Исправить импорт: целостность, URL/redirect, ограничения, файловые границы, предварительный просмотр и подтверждение доверия. Убрать выполнение файлов из «Показать».
3. Стабилизировать ремонт/удаление/отключение, очереди операций и чтение журналов.
4. Исправить тесты и LF-фикстуры, добавить CI. Не выпускать новую сборку, опираясь лишь на успешный frontend build.
5. Выполнить пробную сборку независимого ядра под Windows 7, затем переносить UI на Qt по отдельному плану.

Полная замена интерфейса и подтверждение поддержки старых Windows в рамках диагностики не реализованы. Отчёт служит конкретной основой для следующих изменений.
