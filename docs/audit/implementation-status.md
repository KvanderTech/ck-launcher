# Результат диагностики и перехода на Qt

Дата: 7 сентября 2026 года. Ветка: `improve/security-qt-windows`. Исходная диагностика выполнена на `09b2e88`; реализация основана на `77950d5`, уже включающем исправления автора PR №1. Исходный отчёт остаётся историческим документом и не описывает текущее состояние ветки.

## Что изменилось

Основной интерфейс перенесён на Qt Widgets, игровая логика выделена в общее Rust-ядро. Qt запускает отдельный `ck-launcher-service.exe` и обращается к нему по закрытым stdin/stdout. Нет управляющего HTTP-сервера, WebView2 и обязательного браузерного движка. Старый интерфейс сохранён как переходная оболочка над тем же ядром.

Нативный интерфейс включает библиотеку, создание и запуск Vanilla/Fabric/Quilt, каталог Modrinth с выбором версии, импорт `.mrpack`, управление установленным контентом, аккаунтами, скинами и плащами, Java и памятью, файлами и очищенными журналами. Окно изменяет размер и сохраняет геометрию. Долгие операции выполняются в отдельном процессе, показывают состояние и поддерживают отмену.

## Статус находок исходного аудита

| № | Находка | Реализация |
| --- | --- | --- |
| 1 | Файлы модпака без хешей и политики адресов | Требуются корректные SHA-512/SHA-1 и размер; сверяются все указанные хеши. Проверяются HTTPS, точные разрешённые хосты и каждый redirect. Локальный импорт требует одноразового подтверждения проверенного снимка архива. |
| 2 | Неограниченная распаковка и память | Предварительная проверка всего ZIP, ограничения числа файлов, размеров, сжатия и суммарной загрузки; потоковое скачивание и staging. Ответы каталога также ограничены. |
| 3 | Слабая проверка путей | Общая проверка компонентов Windows: traversal, ADS, device names, reparse points, коллизии имён и служебные пути. Проверяются также корни каталогов миров и журналов. |
| 4 | «Показать» могло выполнить файл | `SHOpenFolderAndSelectItems` выделяет файл без передачи его обработчику запуска. |
| 5 | Java не понимала префикс Windows | Сохранено исправление PR №1 на границе аргументов JVM; добавлена поддержка исходного сокращённого Windows-имени корня загрузчика после canonicalize. |
| 6 | Не было Java 16 | Java 16 добавлена в определение требований, выбор, установку, интерфейсы и тесты. Архив Temurin закреплён контрольной суммой. |
| 7 | Windows 7/8.1 | Отдельная сборка Qt 5.15.2 и Rust target `x86_64-win7-windows-msvc` с собственной стандартной библиотекой. Проверяются импорты всех EXE/DLL: исключены `combase.dll` и системный D3D compiler с зависимостями Windows 8+. Сборка и smoke на современной Windows проверяются автоматически; реальная старая ОС требует отдельного прогона. |
| 8 | Старт ожидал сеть | Локальная библиотека загружается независимо от каталога. Чтение состава сборки больше не обращается к Modrinth и не меняет записи БД. |
| 9 | Не работал ремонт локального `.mrpack` | Хранится проверенный снимок исходного архива и его SHA-256; восстановление не обращается к несуществующим Modrinth ID. Существующие настройки и миры из overrides сохраняются. |
| 10 | Моды расходились с БД | Удаление учитывает `.disabled`, ремонт сохраняет состояние отключения, обновление отдельного мода убирает старое имя. Файловые изменения откатываются при ошибке записи БД. Каталог нельзя заменить обычным файлом. |
| 11 | Неподходящий загрузчик и версии зависимостей | Forge/NeoForge и неизвестные зависимости отклоняются заранее. Соблюдаются закреплённые версии обязательных зависимостей; ограничены циклы и глубина. Мод не превращает Vanilla в Fabric незаметно. |
| 12 | Секреты в исходных журналах | Ограниченное чтение хвоста, общий фильтр полей токенов, Bearer, CLI и Xbox; очищение до передачи в любой интерфейс и экспорт. |
| 13 | Конкурирующие изменения | Общая блокировка изменений с учётом активной игры/установки, эксклюзивные временные файлы и отмена. Обход каталогов ограничен числом элементов и глубиной. |
| 14 | Несогласованные сценарии и отсутствие CI | Кнопка «Играть» запускает выбранную сборку, восстановлена отмена; тесты проверяют задержанную сеть, события и память. Добавлена CI-матрица modern/legacy и переходного frontend. |
| 15 | Фиксированное окно и тяжёлый первый экран | Qt Widgets с DPI-масштабированием и изменяемым размером окна. В переходном frontend тяжёлая страница скинов загружается по требованию: основной JS сократился примерно с 840 до 282 КБ. |

## Проверки

- Rust: 185 успешных проверок в `cargo test --workspace --locked`, включая установщик, авторизацию, обработку путей, хеши, откат файлов и SQLite; без отключения упавших тестов.
- Переходный интерфейс: 36 тестов, production-сборка и проверка npm-зависимостей.
- Qt 6.8.3 и Qt 5.15.2: компиляция, CTest протокола, запуск настоящего ядра с временной APPDATA и создание безвредной сборки; сохранены снимки окна.
- `scripts/test-service.py`: реальный обмен с release-процессом, кириллица и пробелы в путях, цикл создания/удаления, обязательный предпросмотр, отказ аналогу PoC, запрет traversal, повторного подтверждения, ремонт локального архива, сохранение изменённых настроек и удаление отключённого мода.
- OSV: проверены 179 версий зависимостей из реально используемого Windows-графа нового ядра; на дату проверки совпадений с известными advisories нет. Полный разрешённый граф Cargo шире активного графа.
- `scripts/check-legacy-imports.py` проверяет статические и отложенные импорты всех EXE/DLL Legacy на известные зависимости Windows 8+. Проверка обнаружила и помогла исправить неверную привязку `CoTaskMemFree` к combase.dll и лишний D3D compiler из новой Windows. Используется документированный [экспорт Ole32.dll](https://learn.microsoft.com/en-us/windows/win32/api/combaseapi/nf-combaseapi-cotaskmemfree).
- CI повторяет проверки на чистой Windows и упаковывает приложение со всеми Qt DLL. Точное состояние каждого запуска доступно во вкладке Actions репозитория.

Присланный `poc.mrpack` и извлечённый JAR не запускались. Регрессионный архив содержит только безвредные тестовые данные. Подробности статического анализа — в [отдельном документе](poc-mrpack.md); подозрительные бинарники в Git не добавлены.

## Границы результата

Это первая нативная beta, а не обещание безошибочной работы любого Minecraft на любой Windows. На настоящих Windows 7 SP1 и 8.1 ещё нужно проверить вход Microsoft, игровые версии, Java, видеодрайверы и DPI по [матрице проверки](../NATIVE_BUILD.md). Современные дистрибутивы Java могут требовать более новую ОС; доступен ручной выбор проверяемой Java. Qt 5.15.2 требует отдельной политики сопровождения исправлений перед публичным Legacy-релизом.

Хеши и разрешённые источники защищают целостность доставки, но не превращают произвольный мод в безопасный код. Моды работают с правами пользователя после запуска Minecraft; доверие к их автору остаётся необходимым.

Откат файлов покрывает ошибки установки и БД в работающем процессе. Это не журнал восстановления после отключения питания: если процесс аварийно завершится между изменениями файлов и БД, сохранённые `.ck-rollback-*` могут потребовать ручного восстановления. При обычной ошибке отката единственная резервная копия не удаляется. Перед изменением схемы SQLite создаётся согласованная копия базы.

Qt проверяет наличие подходящего нативного выпуска и открывает его страницу. Автоматическая установка подписанного миграционного обновления требует отдельного релизного процесса и имеющегося у владельца ключа Tauri; ключ не запрашивался и не изменялся. Ветка не публикует релизы автоматически.
