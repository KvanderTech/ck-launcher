# План перехода на Qt и поддержки Windows 7/8.1/10/11

## Предлагаемое решение

Перенести интерфейс на **Qt Widgets**, сохранив и выделив Rust-ядро в самостоятельный компонент. Для современных Windows использовать Qt 6; для Windows 7 SP1/8.1 — отдельную сборку на Qt 5.15 с проверенным набором зависимостей. Начальная архитектура — x64, как в существующем проекте. Поддержка x86 требует отдельного решения по Java, памяти и библиотекам Minecraft.

Widgets подходит для библиотеки, настроек, очереди загрузок и журналов: базовый интерфейс может отрисовываться без встроенного браузера. Предпросмотр 3D-скинов следует сделать отключаемой дополнительной возможностью с обычным 2D-изображением при отсутствии подходящего GPU. Qt Quick тоже возможен, но для требования старых видеокарт понадобится отдельная проверка программного рендеринга.

Перенос React в Qt WebEngine не решит поставленную задачу: внутри снова останется браузерный движок с собственными ограничениями совместимости. React-компоненты и CSS потребуется переписать в нативный UI. Логику скачивания, OAuth и целостности переписывать одновременно с интерфейсом не следует.

## Матрица предполагаемой поддержки

| Система | Интерфейс | Что требуется от ядра | Статус |
| --- | --- | --- | --- |
| Windows 11 x64 | Qt 6 Widgets | Обычный Windows-target Rust; проверенные зависимости | Целевой основной вариант |
| Windows 10 x64, минимальную сборку закрепить явно | Qt 6 Widgets | То же; учесть минимальную ОС конкретной версии Qt | Целевой основной вариант |
| Windows 8.1 x64 | Qt 5.15 Widgets | Сборка совместимого Rust-ядра и проверка каждого runtime/WinAPI | Возможность предстоит подтвердить |
| Windows 7 SP1 x64 | Qt 5.15 Widgets | Legacy-target Rust, совместимые библиотеки и компоненты установки | Возможность предстоит подтвердить |

Архивная [матрица Qt 5.15](https://doc.qt.io/archives/qt-5.15/supported-platforms.html) перечисляет Windows 7 и 8.1. [Текущая матрица Qt 6](https://doc.qt.io/qt-6/supported-platforms.html) перечисляет Windows 10 от 1809 и Windows 11, но не Windows 7/8.1. Выбранную точную версию Qt нужно зафиксировать, а её сопровождение и доступные исправления учитывать отдельно: поддержка старой ОС в исторической таблице не означает актуальное обслуживание всех старых сборок Qt.

Начиная с [Rust 1.78](https://blog.rust-lang.org/2024/02/26/Windows-7/), обычные `*-pc-windows-*` требуют Windows 10 — в том числе произведённые ими программы. Существуют [targets `*-win7-windows-msvc`](https://doc.rust-lang.org/rustc/platform-support/win7-windows-msvc.html), но это Tier 3 без готовых стандартных артефактов rustup. Нужна собственная сборка стандартной библиотеки и проверка транзитивных зависимостей. Слепой откат на Rust 1.77 не является решением для современного lock-файла.

Поддержка окна лаунчера, конкретного Java-runtime и конкретной версии Minecraft — три разные вещи. Для старых Windows нельзя автоматически считать доступными все Java из текущего манифеста. Понадобится матрица «ОС × архитектура × Java × Minecraft/загрузчик» и понятный отказ для неподдерживаемых сочетаний. Контрольные суммы всех четырёх текущих Temurin-архивов сверены, но их запуск на Windows 7/8.1 не проверялся.

## Структура после миграции

| Компонент | Ответственность |
| --- | --- |
| `launcher-core` | Профили/SQLite, учётные записи и Credential Manager, метаданные, установка, целостность, управление Java и игрой |
| `launcher-service` | Узкий версионированный интерфейс команд и событий к ядру; без Tauri/WebView |
| `launcher-qt` | Qt Widgets: страницы, формы, отображение прогресса и ошибок; без токенов и произвольного shell-доступа |
| Установщик/обновление | Комплект Qt-библиотек и плагинов, проверка подписей, совместимые каналы modern/legacy |

Практичный первый мост — отдельный дочерний сервис через `QProcess`, обменивающийся ограниченными сообщениями по stdin/stdout. Не нужен открытый HTTP-порт и нельзя принимать произвольные команды ОС из UI. Логи процесса отделяются от протокола, сообщения имеют ID, версию и ограничение размера; ошибки/отмена/завершение процесса обрабатываются явно. FFI — возможная последующая оптимизация после стабилизации границы ядра.

Приватные токены должны оставаться в Rust. UI получает только публичные DTO. У каждой сборки одна очередь мутаций; операция продолжает существовать при переключении страниц. Это перенос уже полезных свойств проекта, а не новая зависимость UI от внутренних файлов.

## Этапы и проверяемый результат

1. **До переноса:** устранить опасный импорт и согласовать исправления запуска из PR №1. Привести тесты к выбранному пользовательскому сценарию.
2. **Проверка выполнимости legacy:** собрать минимальное ядро без Tauri и проверить на чистых Windows 7 SP1/8.1: старт процесса, TLS к нужным сервисам, SQLite, Credential Manager и запуск безвредного Java-класса. Если это не работает, сначала решается состав зависимостей; полноценный UI ещё не переписывается.
3. **Выделение ядра:** убрать `tauri::State`, `Emitter`, runtime-обёртки и UI-обработчики из бизнес-модулей. Ввести обычные Rust-сервисы, события и контракт, который можно тестировать без окна.
4. **Вертикальный сценарий Qt:** локальная библиотека → выбор профиля → проверенная Vanilla-установка → запуск → журнал → остановка. Qt 5 и Qt 6 собираются из совместимого набора исходников.
5. **Полнота возможностей:** Microsoft-вход, Fabric/Quilt, контент Modrinth, безопасный локальный импорт, скины/плащи, восстановление, файловые ассоциации и защита от второго экземпляра.
6. **Выпуск:** комплектование DLL/плагинов Qt, чистая установка, обновление существующих данных, сценарий без интернета, сохранение ключа доверия обновлений и миграционные тесты старой SQLite-базы.

Обновлятор Tauri нельзя просто удалить: у текущих пользователей уже есть закреплённый публичный ключ. Переходный подписанный выпуск должен доставлять новый установщик и сохранять каталог данных. Новый механизм проверяет подписи до замены/запуска; legacy-канал не должен случайно получить бинарник для Windows 10+.

## Приёмка

Проверить каждую целевую ОС на чистой виртуальной машине и хотя бы одно слабое физическое устройство: стандартный пользователь, кириллическое имя, пробелы, DPI 100/125/150/200%, небольшой экран, отсутствие Java, пропадание сети, отмена установки, битый архив, заполненный диск, обновление старой базы и отказ внешнего сервиса. Для Win7 дополнительно проверить совместимые TLS/сертификаты, runtime и компоненты установки; сами флажки версии в манифесте не исправляют отсутствующие WinAPI.

До завершения этой приёмки корректная формулировка — «legacy-сборка разрабатывается», а не «поддерживает любые Windows». Оценку сроков следует делать после этапа проверки ядра на Windows 7: именно он определит масштаб работ, а не внешний вид окна.

Сопутствующие работы: определить лицензию исходников проекта, проверить условия распространения выбранной Qt-сборки и сохранить атрибуцию сторонних ресурсов. В репозитории сейчас не найден отдельный LICENSE; выбор лицензии остаётся за владельцем.
