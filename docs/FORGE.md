# Forge в нативном лаунчере

Начиная с 0.2.3-beta.1 нативная оболочка поддерживает сборки с зависимостью `forge`: создание сборки, установку выбранного релиза Modrinth, импорт `.mrpack` и восстановление через настройки сборки.

## Установка

Версия из `modrinth.index.json` используется точно, без замены на Vanilla. Для новой пустой сборки выбирается recommended, а при его отсутствии latest из официального списка Forge. Поддерживается формат клиентского установщика `spec: 1` для Minecraft 1.13 и новее; старый формат 1.12.2 и ниже, NeoForge и сочетание нескольких загрузчиков отклоняются явно. Это не означает, что каждая историческая версия Forge проверена на запуск.

Установщик скачивается только с `maven.minecraftforge.net`, его SHA-1 сверяется с опубликованной по HTTPS контрольной суммой. Профиль внутри JAR должен соответствовать запрошенным Minecraft и Forge. Установщик исполняется с подходящей Java через `--installClient` в новой временной папке внутри сборки. Он получает пустой тестовый `launcher_profiles.json`, а не профили официального лаунчера. Токены аккаунтов и внешние переменные JVM ему не передаются.

После успешного завершения в сборку переносятся только обычные файлы из `libraries` и `versions`. Пути проверяются против выхода за каталог и reparse points; есть ограничения числа и размеров файлов. Контрольные суммы записываются в `versions/<id>/forge-installation.json`. Незавершённая установка не активируется, отмена и таймаут останавливают дочерний процесс. Миры и пользовательские конфигурации не входят в этот этап.

Перед запуском проверяется также инвентарь сгенерированных Forge файлов. Если он повреждён, используйте **Настройки сборки → Переустановить и восстановить**. Для исправной установки официальный установщик повторно не запускается; профиль восстанавливается из проверенного локального JSON.

Forge требует дополнительных аргументов JVM. Они разрешены отдельным ограниченным обработчиком: module path должен состоять из проверенных библиотек этой сборки; доступны только известные `add-opens`/`add-exports` и проверенные свойства Forge. Общие запреты на Java agents, подмену памяти и внешние пути не ослаблены. Сам Forge и моды исполняют код с правами пользователя — проверка целостности не делает произвольный мод безопасным.

## Проверки

Автотесты проверяют координаты версий, отсутствие подмены загрузчика, смешанные зависимости, повреждённые и отсутствующие файлы инвентаря, ограничение module path и сохранение общей политики JVM.

Сетевая проверка выполняется отдельно от CI, на изолированных данных без аккаунта. Тестовый пример — [Zombie Invade 100 Days, 2.3-Fix](https://modrinth.com/modpack/zombie-invade-100-days/version/M8j2mfGj): Minecraft 1.20.1, Forge 47.4.10, 130 элементов установленного контента. Файлы модпака и тестовая папка не включаются в репозиторий или релиз.

Для проверки подготовки запуска установите сборку через сервис с отдельным `APPDATA`, затем укажите путь к её `CKLauncher` в `CK_FORGE_SMOKE_ROOT` и запустите:

```powershell
cargo test -p ck-launcher-core installed_forge_builds_a_valid_demo_launch -- --ignored --nocapture
```

Это opt-in тест с сетевой загрузкой игровых ресурсов. Он проверяет параметры реального запуска и записывает демонстрационную команду с `--demo`; вход Microsoft не обходится в пользовательском приложении. Никогда не используйте тест с рабочей папкой аккаунта.

Windows 7/8.1, конкретные версии Java и модпаки требуют отдельных проверок на соответствующих ОС. Успешная сборка Legacy не подтверждает совместимость современных модов со старой системой.
