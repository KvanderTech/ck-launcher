# Нативный ЦК Лаунчер 0.2

Основной интерфейс — Qt Widgets. WebView2, Node.js и браузерный движок пользователю не нужны. Игровая логика находится в `crates/launcher-core`; `ck-launcher-service.exe` связывает её с Qt через закрытые каналы стандартного ввода/вывода. Сетевой порт для управления лаунчером не открывается.

## Интерфейс beta.2

Qt использует оригинальные изображения и компоновку лаунчера. Библиотека адаптируется к ширине окна, каталог содержит карточки и фильтры, файлы/миры/журналы доступны внутри страницы сборки. Скины отображаются объёмно средствами QPainter: мышь вращает персонажа, анимация не требует OpenGL. Наведение и нажатие кнопок анимированы без смещения элементов; настройка «Плавные анимации» отключает движение.

Публичные иконки и текстуры загружает Rust-ядро с Rustls. Qt 5 не требует отдельных DLL OpenSSL для этой функции. Источники и перенаправления ограничены HTTPS и точным списком хостов; максимум изображения — 2 МБ, декодируемые размеры — 2048×2048. Очередь UI ограничена четырьмя одновременными запросами, кэш — 48 МБ. Для WebP нужен модуль Qt Image Formats: у Qt 6 он устанавливается как `qtimageformats`, у Qt 5 — одноимённый базовый архив. CI включает его в оба канала.

## Два выпуска Windows x64

| Канал | Интерфейс | Ядро | Назначение |
| --- | --- | --- | --- |
| modern | Qt 6.8.3, MinGW 13.1 | Rust 1.90, x86_64-pc-windows-msvc | Windows 10 1809+ / Windows 11 |
| legacy | Qt 5.15.2, MinGW 8.1 | Rust nightly-2025-09-18, x86_64-win7-windows-msvc, build-std | Windows 7 SP1 / 8.1; Windows 8.0 — отдельная непроверенная цель |

32-разрядная Windows и Windows ARM пока не входят в матрицу. Обычное ядро Rust для Windows нельзя просто положить рядом с Qt 5 и назвать выпуск совместимым с Windows 7: для Legacy собирается собственная стандартная библиотека Rust. Нужна актуальная для соответствующей ОС система сертификатов и установленные системные обновления.

Сборка и запуск тестов в Windows 10/11 или Windows Server не заменяют проверку на реальных Windows 7 и 8.1. До публичного объявления полной поддержки Legacy нужно пройти матрицу ниже. Qt 5.15.2 — воспроизводимая исходная точка для старых ОС; перед публичным распространением нужен сопровождаемый набор исправлений Qt 5 или согласованная с владельцем политика обновлений. Версии Qt заданы явно и меняются после повторных проверок.

## Запуск готового архива

Распакуйте архив целиком в отдельную папку и запустите `ck-launcher-qt.exe`. `ck-launcher-service.exe`, библиотеки Qt и папка `platforms` должны оставаться рядом. Скопировать один EXE недостаточно. Лаунчер использует прежний `%APPDATA%/CKLauncher`: аккаунты, профили, миры и выбранная Java сохраняются. До изменения схемы SQLite создаётся согласованная резервная копия `launcher-before-schema-*.sqlite3`, включая данные WAL.

Для запуска лицензионной игры войдите через Microsoft. Отсутствие каталога не блокирует открытие библиотеки; игра без сети запускается при наличии необходимых игровых файлов и пригодного сохранённого сеанса. Доступность конкретной версии Minecraft на старой ОС зависит от Java, загрузчика, модов и видеодрайвера. Java 16 выбирается отдельно для версий, которым она требуется; подмена на Java 17 не выполняется. Если современный дистрибутив Java не запускается на старой Windows, используйте ручной выбор совместимого `java.exe`; проба проверит требуемую основную версию.

## Сборка из исходников

Для modern установите Rust 1.90 MSVC, Visual Studio Build Tools, CMake 3.20+, Ninja, Qt 6.8.3 с MinGW 13.1. Выполните в корне репозитория:

```powershell
cargo test --workspace --locked
cargo build --release -p ck-launcher-service --locked
cmake -S apps/qt -B build/qt -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=C:/Qt/6.8.3/mingw_64
cmake --build build/qt
ctest --test-dir build/qt --output-on-failure
./scripts/package-native.ps1 -QtBin C:/Qt/6.8.3/mingw_64/bin -BuildDir build/qt -ServicePath target/release/ck-launcher-service.exe -Channel modern
python scripts/test-service.py dist/modern/ck-launcher-service.exe
```

Каталоги `dist/modern` и `dist/legacy` содержат только результаты сборки: упаковщик очищает каталог выбранного канала перед пересборкой. Не храните там пользовательские данные.

Компилятор Qt и его `bin` должны находиться в PATH. Для старых MinGW используйте папку сборки и инструменты без кириллицы: старый GNU linker имеет ограничения обработки Unicode в путях; это ограничение сборочного инструмента, а не путей пользовательских сборок игры.

Legacy: установите `nightly-2025-09-18` и компонент `rust-src`, соберите ядро с `--target x86_64-win7-windows-msvc -Z build-std`; установите Qt 5.15.2 `mingw81_64` и добавьте `-DCK_LEGACY_WINDOWS=ON` к CMake. Полные воспроизводимые шаги находятся в `.github/workflows/native.yml`. Для статического CRT в ядре CI использует `-C target-feature=+crt-static`; Qt остаётся динамической библиотекой.

## Проверка выпуска

`scripts/check-legacy-imports.py dist/legacy` проверяет известные несовместимые статические и отложенные импорты DLL/API, включая combase.dll. Эта проверка не заменяет запуск на целевой ОС. Для Legacy не включаются ненужные Qt Widgets библиотеки ANGLE и современный системный D3D compiler.

На Windows 7 SP1, 8.0, 8.1, 10 и 11 отдельно: чистая установка без WebView2; вход Microsoft и отмена входа; Unicode/пробелы в пути; создание и запуск Vanilla/Fabric/Quilt; Java 8/16/17/21 по применимости; отсутствие сети; отмена скачивания; импорт безопасного архива; отклонение файла без хеша, Zip Slip и архивной бомбы; сохранение отключённых модов при восстановлении; перенос сборки в trash; смена DPI 100/125/150/200%; закрытие и повторный запуск. Проверять Minecraft с современными модами нужно отдельно от самого интерфейса.

`--smoke` запускает интерфейс с настоящим ядром и отдельной временной APPDATA, создаёт безвредную Vanilla-сборку и завершает процесс; игру и моды не запускает. `--screenshot PATH` сохраняет окно этой проверки; `--page home|library|catalog|skins|settings|details|logs` выбирает экран. `scripts/test-service.py` проверяет реальный протокол, локальную библиотеку, отказ опасным путям и безвредный аналог присланного PoC.

`ctest` дополнительно запускает `ui-test` с отдельным тестовым сервисом. Он проверяет навигацию, две колонки библиотеки при 1280×720 и одну при 980×620, отсутствие обрезки по горизонтали, карточки скинов, фильтры каталога, подбор версии Fabric, сохранение памяти, меню аккаунтов, анимации и ранние ошибки запуска. `ui-fixture.exe` не содержит аккаунтов и не запускает игру; в пользовательский архив не включается. Снимки сохраняются в `build/qt/ui-screenshots` и артефактах CI. Эти проверки подтверждают поведение интерфейса; вход Microsoft и запуск лицензионной игры проверяются отдельно на целевых ОС.

## Обновления и переход

Qt показывает только выпуски с нативным артефактом своего канала и открывает точную страницу выпуска этого репозитория. Неподписанный установщик автоматически не скачивается и не запускается. Прежний интерфейс в `app/` оставлен как переходная оболочка над тем же ядром; его подписанное обновление Tauri и публичный ключ сохранены. Публикация миграционного установщика требует существующего закрытого ключа владельца; он не входит в исходники. Не направляйте старый `latest.json` на неподходящий Qt ZIP.
